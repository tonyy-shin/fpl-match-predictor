## Goal for today
- Download football-data csv files for all seasons using request calls.
- Convert football-data csv files to parquet.

## What I did
### 1. Downloading the CSVs
- URL pattern and season codes: "/mmz4281/{season}/E0.csv" where season format is e.g. 9798
- How the script works (requests, saving raw bytes): 
    1. request csv file using url
    2. raise for any errors
    4. write to specified output path 
- Issue hit: the Eo vs E0 typo returned an HTTP 300 page, and raise_for_status() didn't catch it
- Fix: Eo.csv -> E0.csv

### 2. Converting CSV to Parquet
- First crash (ParserError, 0405 and 0304):
  - Cause: has wider rows than header columns
  - Fix: 
        1. read the rows and put it into a list
        2. get max row width out of all the rows
        3. get number of header columns
        4. add extra headers from range(number of headers, max row width) as extra_{i}
- Second crash (UnicodeDecodeError, 0405):
  - Cause: old data used windows encoding 
  - Fix: try utf-8 at first and if it fails fall back to windows encoding(latin-1)
- Silent issues found (BOM, blank rows, unnamed columns):
    - BOM Cause: files start with invisible bytes (encoding specifier) so first column DIV becomes /ufeffDIV
    - Row/columns Cause: had trailing rows and columns (assuming the owner of the csv file left trailing rows and columns using excel...)
    - Fix: 
        1. BOM
            - decode with "utf-8-sig" instead of "utf-8", which removes the invisible bytes when the file is turned into text
        2. Row/Columns
            - dropna(axis=0, how="all") removes rows where all cells are empty
            - dropna(axis=1, how="all") removes columns where all cells are empty

### 3. Verification
- Row counts per season: (19+19)*10=380 for recent years and (21+21)*11=462 for past years
- Column count range and what it means: the number of columns that the season has data for (range 7-132)

## Concepts I learned
- encoding: old data may use different encoding from utf-8
- having wider rows than the header column makes pandas crash
- with header=None, pandas uses the length of names= as the number of columns. I built names to be as long as the widest row, so every row fits
- you can specify the headers separately by using names=columns
- by default pandas turns text like "NA" or "null" into missing values. I turned that off (keep_default_na=False) so only empty cells become missing

## Decisions made
- Why raw CSVs are saved unchanged: I can always go back to the original data if there are any issues when converting or transforming the original data
- Why all columns are read as strings: 
    - pandas defaults to converting each cell when data type not specified
    - values such as 03/04 may be converted to dates
